# Light map-line correction for the TV episode map — no Textual editor

Correcting the episode map at the `rip tv` confirm table (and the chapter-split boundary table) happens through whole-map answers — one `›` line of comma-separated rows (`0=e,1=e,2=1`), parsed per-row so a bad row is named and skipped and the session never restarts — instead of an interactive Textual editor. The Light console contract (scrollback, pipe/NO_COLOR/TERM=dumb fallback, rich-only, one answer per prompt) already governs every other screen and its test suite; a Textual app would add a dependency, a second UI to maintain for one screen, and a new test style — while the crash-on-typo that motivated the TUI idea was a parsing bug (`parse_fix_rows` raising straight through the confirm loop), not a Light-tier limit. Revisit if map rows still fight the operator after a few real discs.
