# Rip-complete gate: part-set declaration, not a done marker

A movie staged between the discs of a multi-disc set looks identical to a finished single-disc movie — disc 1 renames, promotes and validates honestly — so transcode could encode half a movie, and the library copy would then block the disc-2 merge forever via the Already-in-library skip (the 2026-11-13 session: `logs/rip.jsonl` proved the junk-label gate had held every mid-rip file across 1,676 records, but nothing holds the between-discs window; the Two Towers encode that same day is the exact shape at risk). Rather than a manual done marker — the retired `rip-DONE` habit — completeness is declared at rip time: `--part 1` declares the set (disc 1 wears `.p1`), no flag means single-disc and complete at rename, and the only prompt fires at the end of a `--part N≥2` run (`More discs for <movie>? [y/N]`, bare Enter completes the set, the count recorded in the validation file). Transcode defers incomplete sets loudly — never encoded, never a session-cap slot, never disposed. A prompt on every rip was rejected: no interruptions unless actively managing multi-disc sets.

The same session pinned the failed-rename bug behind the stale junk skips: MakeMKV sometimes names its output from the disc's volume label (`X-Men- Apocalypse_t00.mkv`), and `looks_real` let it survive renaming — the rename guard now uses transcode's own rule, real iff the base ends `(YYYY)`.
