# Fast scan is the default gate; the full MakeMKV scan escalates on failure or ambiguity

`rip_preamble` ran a full `makemkvcon info` (minutes) before any prompt, so every rip waited on the scan. We replace the gate with a fast read — `lsdvd` straight on the block device (DVD; no mount, no sudo) or `ffprobe bluray:` (BD) — yielding titles as durations in seconds. The full scan is demoted to an escalation, fired synchronously when the fast read fails at all (tool missing, nonzero exit, unparseable output) or finds two titles within ±1s (duplicate/decoy/angle playlists), or when a movie `-T` menu is requested, or when a TV play-all is detected (ADR 0008 — the rip skips it, and skipping needs real title numbers).

## Consequences

The fast path yields scanner title numbers that don't match MakeMKV's, so TV rips `all` and joins staged `_tNN` files to scanner titles by duration (±1s) before renaming. The escalation path keeps MakeMKV numbers and rips per-title with no join. Media type, volume label, and no-disc detection come from an early-killed `makemkvcon` DRV-line sniff, so the existing DRV parsers (`_parse_media`, `_parse_label`) stay in place unchanged. The DVD fast read addresses the device the DRV line named (falling back to the `disc:N -> /dev/srN` guess only when the DRV line lacks a path); if device-direct `lsdvd` proves flaky in practice, the arm can be deleted outright — the escalation already covers every failure, so nothing else would change.
