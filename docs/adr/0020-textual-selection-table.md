# One Textual selection table for every pre-rip choice

Supersedes ADR 0017 (light map line over a textual editor). Every pre-rip decision — movie titles, TV titles, CD tracks — happens in one Textual selection table: a transient app launched at the decision moment that exits back into the rich run view (ADR 0012–0014 untouched — the run view stays framed scrollback, not a TUI). Six universal columns (`#`, length, size, audit, action, notes); medium-specific verbs (movie: main/extra/skip with exactly one main, `m` moves it; TV: episode/double/extra/skip; CD: rip/skip). The audits prefill every action — main arbitration, episode guess, play-all detection — and the operator restates any action at the cursor: typed values (`3`, `3-4`, `e`, `s`, `m`), Space-marked rows filling in order from one typed number. Enter accepts, echoing the accepted table as plain lines into scrollback before the drive spins; `q` quits; Ctrl+C interrupts. Episode clash and staged-episode violations block Enter as red rows; unfilled episodes warn without blocking; the ratio audit never gates — durations grade, they never assign.

Why the reversal: ADR 0017 stayed Light because the motivating crash was a parsing bug, with a revisit clause if map rows fought the operator on real discs. What actually fought was broader — three separate grammars for the same act (TV map rows, the movie gate's rip/q, CD's cyanrip `-l` flags), a range prompt layered over a prefilled guess, and `-T`/`-E`/`-i` flags shaping the rip before any table appeared. The map line never got its fair trial (block rows unshipped) and is deleted rather than kept as a fallback: without a terminal the flow refuses to start — rip flows are interactive by design — so there is one grammar, the table, not two. Its per-row semantics survive as in-table behavior: a bad edit is named at the row, never restarts the run. Deleted with it: `parse_fix_rows`/`apply_fixes`, the TV confirm loop, `ask_range`, the movie main-pick prompt, `chapter_split.parse_fix`, and the flags. The chapter-split boundary table migrates onto the same component after the three main flows ship. Headless Pilot tests cover the table; the run view keeps its plain-line pipe fallback (passive output, unaffected).

Revisit trigger, concretely: none scheduled. A whole-run Textual app was considered and rejected — it would re-buy terminal-native scrollback as a widget, keep the pipe fallback anyway, and rewrite a working, tested output layer, buying no new capability.
