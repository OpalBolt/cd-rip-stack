# PR-gated main with an AI-maintained changelog

392 commits went straight to main as one conscious stream — fine while the repo had no users, but a skive user now rides main via `mise run update` (`git pull --ff-only` + editable reinstall), so a broken main is a broken user machine, and "what changed?" had no answer shorter than `git log`. The deciding anecdote: ruff's B006 autofix on the very first machine-edited pass silently hijacked `None` as a sentinel where `None` meant "resolve failed" — only the 1086-test suite caught it. Machines mass-editing this repo need a gate that is not the author's own attention.

Main is now PR-gated. Every change lands as a pull request, squashed to one commit per bundle, so main's log mirrors `CHANGELOG.md` 1:1. The division of labor is the security model: agents prepare — branch, verify locally, write the PR text into `.scratch/prs/` — but hold no GitHub credentials and never touch the remote; the operator runs `scripts/open-pr.sh` (push + `gh pr create`), reviews, and presses merge. CI must be green before merge: pytest, ruff check, ruff format, and mypy (basic, bodies checked, `skive/` only — ADR-grade pragmatism, not strictness theater). Branch protection enforces all of it, administrators included; zero required approvals — the operator's own review is the approval. The changelog is AI-written and human-vouched: every `feat`/`fix` PR adds its line under `## Unreleased` in `CHANGELOG.md`, and the approver verifies the entry exists before merging — the same checks-and-balances split as the code itself.

Rejected: staying direct-to-main with tags and release notes (no gate against a bad push, and the user pulls daily, not at releases); a hand-written changelog assembled at release time (homework that silently stops happening); requiring approvals from a second person (there is no second person — the operator review is the human gate); giving the agent GitHub credentials to automate the loop (the credential boundary is worth the one manual command). No tags or versioned releases yet: the user rides main and the changelog satisfies follow-along; revisit the day the user asks "what changed since I last pulled".
