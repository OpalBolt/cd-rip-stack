# The skive box — one container, reproducibility over convenience

Every machine becomes a ripping and encoding machine the same way: clone the repo, fill in `.env`, build the image, run `./skive doctor` until its table is green. The box is one home-isolated Fedora container that replaces both earlier environments — the distrobox built by a setup script and the Arch host install path — carrying every tool plus skive baked in at build time, so every machine runs the identical binary and an update is `git pull` and a rebuild. The wrapper `./skive` is the only door: with arguments it runs that skive command in the box with a TTY, without them it opens a shell — and it is the seam a browser-for-a-CLI (a ttyd-style terminal) attaches to later. `skive doctor` is the readiness gate: drives, share mounts, MakeMKV key, tesseract languages, and encode capability in one table, nonzero exit when a prerequisite is missing — it checks and never fixes.

Considered and rejected: keeping the distrobox (its promise was convenience — a seamless share of the host — but its default `/dev` share never did hand over the optical drives, which is the exact wall this box fixes: compose passes `/dev/sr*` and `/dev/sg*` explicitly, and the host owns the drives and the NFS mounts, lifting the "skive never mounts" rule one level); a bind-mounted or editable skive instead of the baked one (it drifts — the point is that every machine runs the same thing); and a doctor that repairs (unpredictable; the user stays in charge of the machine).

Consequences: podman is the documented engine, with `docker compose` driving the same file untested-but-expected. MakeMKV's home persists on a named volume so its settings and data files survive container runs. And this supersedes the write-nothing part of ADR 0016: a key declared through the environment (`MAKEMKV_KEY`, passed by compose from `.env`) is now written into MakeMKV's `settings.conf` at startup — idempotent, the env key always winning — so a key rotation is a one-line `.env` edit on every machine. With no env key the remind-only doctrine of 0016 stands unchanged, and skive still reads its environment, never a `.env` file: compose reads `.env`.
