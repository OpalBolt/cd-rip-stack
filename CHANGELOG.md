# Changelog

Notable user-visible changes to skive. Entries are added by the AI under
`## Unreleased` as part of every `feat`/`fix` PR; the approver verifies the
entry exists before merging. At release time, Unreleased entries move under a
dated heading.

## Unreleased

- feat: `-e auto` resolves a three-rung encoder ladder from a per-profile
  vainfo probe (once per run): HEVC entrypoints → `ffmpeg hevc_vaapi` CQP
  28, H.264-only → `ffmpeg h264_vaapi` QP 28 — a new rung that keeps the
  crop gate and bwdif but drops VCN's 64-px alignment crop — and neither →
  CPU x265 fast unchanged; `-e vaapi` accepts either hardware rung and
  fails fast on a box with none. QP 28 replaces CQP 24 on every hardware
  rung: a per-rung calibration that happens to be unified, not an
  equivalence claim (QP numbers do not transfer between encoders).
- feat: `skive doctor`'s VA-API row reports encode profiles — HEVC +
  H.264, HEVC only, H.264 only, or none, with decode-only (VLD)
  entrypoints never counted — so a box's rung in the `-e auto` ladder
  reads straight off the table.
- build: the box image installs the i965 VA driver (`libva-intel-driver`)
  beside the freeworld Mesa swap — the modern Intel driver never loads on
  Ivy Bridge (Gen7), so the W530's HD 4000 iGPU gets its H.264 encode
  entrypoint from i965.
- feat: video-library audio is lossy-only on every backend — lossy tracks
  copy, lossless tracks (PCM, FLAC, ALAC, TrueHD, DTS-HD MA) drop when a
  lossy track survives, and an all-lossless title transcodes every track
  to ac3 with channels kept; the hardware rungs ffprobe-classify each
  track before encoding and refuse the item on an unreadable probe, while
  the HandBrake paths approximate the rule with a lossy-only
  `--audio-copy-mask` plus the ac3 fallback.
- feat: `scripts/audit_lossless_audio.py` audits the existing library
  against the lossy-only audio rule — a dry run by default, `--fix`
  remuxes each offending file audio-only through a verified temp (video
  and subtitles stream-copied, lossless audio transcoded to ac3; any
  failure leaves the original untouched); the music library's FLAC is by
  design and never in scope.
- build: `scripts/info-bundle.sh` — run on any box to gather its encode
  capability into `info-bundle.txt`: VA-API entrypoints, drivers, ffmpeg
  encoders and a 10 s 1080p bench per candidate backend, so the encoder
  choice for a box rests on measurements
- feat: `skive doctor` validates the TMDB key against the API's
  validate-key endpoint — a rejected key (401) fails the table while an
  unreachable API only warns; `require_online` now says "rejected"
  instead of "unreachable" on a 401, so a bad `TMDB_API_KEY` no longer
  reads as a network problem
- fix: the box starts on single-drive machines (the rip box) — the optical
  device override is now generated by the `./skive` wrapper from the
  `/dev/sr*` and `/dev/sg*` nodes the host actually has, replacing the
  checked-in `compose.rip.yaml` that hardcoded a two-drive layout and died
  on `stat /dev/sr1` wherever the second drive does not exist
- fix: real-looking disc labels without a year ("X-Men- Apocalypse") no
  longer dodge the staged-file rename — `rename_staged` now skips only
  promoted names (this display or any `(YYYY)` tail, the shape transcode's
  junk guard accepts) instead of the old looks-real heuristic, so such
  discs land in transcode's queue instead of its junk-skip lines
- fix: the box starts on drive-less machines (the transcode box) — optical
  device nodes moved to `compose.rip.yaml`, which the `./skive` wrapper adds
  only when `/dev/sr*` exists on the host (a device compose lists must exist
  at container create), and `skive doctor` skips the drive, makemkvcon, and
  key checks as warns on a box with no optical nodes instead of failing them
- feat: the skive box — one Fedora container (Containerfile + compose)
  driven through a `./skive` wrapper replaces the distrobox setup script
  and the Arch host install path; clone, build, `./skive doctor` is now the
  one setup path on any machine.
- feat: a `MAKEMKV_KEY` declared in the environment self-heals at startup —
  skive writes it into MakeMKV's settings.conf (idempotently; the env key
  always wins), so key rotation is a one-line `.env` edit. With no env key,
  the remind-only behavior stands.
- feat: `skive doctor` checks the machine in one green table — drives, share
  mounts, MakeMKV key, tesseract languages, encode capability — and exits
  nonzero when a prerequisite is missing; it checks, never fixes.
- fix: a disc with several forced subtitle tracks in one language (e.g. two
  English forced tracks) shipped duplicate sidecars with the same name; now
  the track with the most cues wins and only one sidecar is written.
- backfill: OCR now runs on a local copy of each MKV instead of reading the
  NFS file many times, and a new `-j N` option processes N files in parallel;
  an unexpected error on one file no longer aborts the whole library run.
